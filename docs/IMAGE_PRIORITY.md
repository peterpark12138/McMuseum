# 图片考古工作表：优先级与检索方法

> 配套文件：`data/image_priority.csv`（62 行，逐个待补图的单品 + 待你填写的候选列）
> 生成时间：2026-10-13 ｜ 数据口径：`data/nostalgic_products.json`（98 款）

这一版**没有增加采集工具的复杂度** —— 瓶颈确实不在代码，而在发现素材、核实身份、确认许可。
本文把「先找谁、怎么找、怎么记」固化下来，`data/image_priority.csv` 就是逐条核对的载体。

---

## 一、优先级是怎么排出来的（规则透明，可手工复算）

只对 **缺图（`image_status = missing`）** 的单品排序，打分三项相加：

| 信号 | 取值 | 理由 |
|---|---|---|
| `evidence_level` | A=3 / B=2 / C=1 | A 级已有官方来源引用 → 找到官方素材的概率最高 |
| 是否有确切年份线索 | 有=1（从 `era` / `first_seen` / `last_confirmed_sale` 中提取） | 有年份才能在官网页存档、当年报道里定向翻档案 |
| 是否带高辨识度标签 | 有=1（`话题王 / 经典 / 颜值 / 国民 / 爆款 / 脑洞`） | 识别度高的产品才值得先投入 |

排序后取前 20 为 **Tier 1**，其余 29 为 Tier 2。

**Tier 1 的实际构成**：16 / 20 是 `evidence_level = A`，16 / 20 有确切年份线索。

### 两个刻意的取舍（请复核）

1. **没有采用"票数"作为优先级依据。** 我读了一次真实共享榜：目前**只有 3 款有票**
   （摇摇薯条 57 / 香芋派 57 / 樱花麦旋风 33），而这 3 款**都已经有图**了。
   用票数排序会让所有缺图产品并列为 0，排不出顺序，所以改为上面的综合信号。
2. **剔除了 6 款"缺图但仍在售"的产品**：热香饼、热朱古力、麦辣鸡腿堡、巨无霸、麦香鸡、双层吉士堡。
   它们不是怀旧下架品，且随时可从现售官方菜单取图 —— 不该占用怀旧考古的优先队列。
   如果你希望顺手补齐，它们单独排即可，不必跟下架品抢资源。

### 另一条独立工作流：26 张已有图的 provenance

这 26 张**不缺图，缺出处**。它们的问题是"图在仓库里，但说不清来自哪个网页"，
所以它们的任务是**查证来源**，不是找新图 —— 与上面 49 款是两条不同的工作流，不要混在一起推进。

## 二、CSV 怎么用（逐列说明）

| 列名 | 已填 / 待填 | 说明 |
|---|---|---|
| `rank` `tier` `id` `name` `official_name` `aliases` `category` | 已填 | `aliases` 是把名字括号部分剥掉后的别名与官方名的并集（如「榴莲麦旋风（苏丹王榴莲）」→ 「榴莲麦旋风」） |
| `year_clue` `era` `first_seen` `last_confirmed_sale` | 已填 | **时间线索**，定向翻年份档案就用这几列 |
| `evidence_level` `verified` `tags` | 已填 | 现有可信度，也是本次排序依据 |
| `cited_sources` | 已填 | **最重要的线索**：项目原先引用过的官方页面/报道，找图就从这里顺着走 |
| `search_terms_zh` | 已填 | 3–4 组中文检索词（产品名 / 产品名+年份 / 限定宣传 / 别名） |
| `source_priority` | 已填 | 检索时的来源优先级提示 |
| `candidate_url` | **待填** | 你找到的候选图片 URL（放**原始图**，不要放搜索结果缩略图链接） |
| `source_page` | **待填** | 出处网页（图片所在的那篇文章/那个活动页） |
| `source_type` | **待填** | `官方` / `媒体` / `消费者` / `AI 复原` |
| `rights_ok` | **待填** | 使用许可判断：`allowed` / `unknown` / `restricted` |
| `img_date_guess` | **待填** | 这张图大致的年份/季节（用于判断是不是"当年的样子"） |
| `note` | **待填** | 包装差异、是否为复原图、任何需要提示的不确定项 |

填完后把它交给下一段流程：只有 `rights_ok = allowed` 的候选才会被下载入库，
其余一律只用链接与说明留档、**不落盘**。

## 三、来源优先级（照你这个顺序试）

1. **官方历史素材**：麦当劳中国官网（含当年的推广活动页）、官方微博 / 微信公众号的活动推文、官方海报。
   名称与外观最可核实；注意"官方发布 ≠ 允许任意转载"，许可必须在 `rights_ok` 里记下来。
2. **新闻媒体 / 行业报道**：产品上市新闻、限定季盘点。
   适合补官网页面已失效的旧产品，也能佐证年份与限定状态。
3. **消费者历史照片**：晒单、论坛存档、旧帖。
   可能挖到稀有产品，但**必须核实产品身份与许可**，确认不了就不要当作该产品的官方图。
4. **AI 辅助复原**：只在确实找不到历史照片时使用。`source_type` 必须写 `AI 复原`，
   落库时 `image_status` 标 `reconstruction`，**绝不**冒充历史实拍。

### 明令禁止

- 不把搜索引擎缩略图当原始图；不绕过登录 / 付费墙 / 反爬；不批量抓取社交平台图片。
- 没有明确许可，不把外部图片打包进公开仓库。
- 找不到图就用统一占位卡，**不拿别的产品图顶替**。

## 四、下一步的衔接

1. 你按 Tier 1 顺序逐条填充 CSV（建议先做 5 款跑通流程，再批量推进）。
2. 我按已填的候选做**下载 + magic bytes / 尺寸 / SHA256 去重 + 稳定文件名**检查。
3. 入库时状态默认 `unverified`；只有 `cited_sources` 与 `source_page` 都对得上、且你能复核的那批，
   才允许升为 `verified`（这一点由 `image_research.py verify` 强制：自称 verified 却没出处会直接判错）。
4. 每批入库后跑：`selfcheck.py`、`image_research.py verify`、`smoke_http.py`、`test_scenarios.py`。

> 这份排序是**规则驱动的近似值**，不是权威结论。若你认为某款应当提前，
> 直接调整 CSV 的 `tier` / 顺序即可 —— 排序的目的是让你先啃"最容易证实、最容易被认出来"的那批，
> 而不是让它替你做判断。
