# DEMO_SCRIPT · 60–90 秒演示脚本

## 先说现有 `docs/demo.gif` 够不够

**不够。** 实测（用 GIF 块解析，非目测）：

| 项 | 实测值 | 结论 |
|---|---|---|
| 尺寸 / 帧数 | 960×540，146 帧 | 画面够用 |
| 总时长 | **约 22 秒** | 低于 60–90 秒目标 |
| 覆盖内容 | hero / 大厅 / 搜索 / 投票弹窗 / 复活榜 / 领奖台 / 在售对比 / 营养标签（8 个浏览态） | 只讲了"能看什么" |
| 缺失 | 真实投票回执、重复投票被拦截、共享榜与演示数据的区分、仓库入口 | **核心价值没讲到** |
| 风险 | 其中的「投票弹窗」是改造前的样子（现在是「🔒 本机投票」灰态） | 直接用会误导 |

所以本文件给出**可照着录的 60–90 秒脚本**。现有 `demo.gif` 保留作「浏览片段」，
但**不要**单独当作完整演示提交——它没展示任何"投票真实发生并被去重"的证据。

> 硬规则：**只录已验证的功能**。下面每一段的"预期画面"都是本机实测过的真实输出，
> 没有一段需要伪造成功结果；若某段因缺凭证跑不出来，脚本里给了替代拍法。

---

## 录前准备（一次性的，不出现在视频里）

```bash
cd McMuseum
# 终端 A：公开演示模式（无需任何 Token）
MCMUSEUM_DEMO=1 PORT=8000 python3 web/serve.py
# 终端 B：留着跑 CLI
```

⚠️ 录屏前确认：**终端里不要出现 Token**，`.env` 不要打开，
浏览器开发者工具的网络面板不要展开（避免 Authorization 头入镜）。

## 第 3 段｜26–48 秒：一次真实投票怎么发生（CLI / Skill）

- **画面**：切到终端，执行
  ```bash
  python3 scripts/revival.py vote --product sakura_mcfloat --from-mcp
  ```
- **预期真实输出（二选一，都不要剪）**：
  - 首次投票：
    ```
    ✅ 麦当劳会员投票成功！《樱花麦旋风》
       基础票 1（登录确认）+ 积分票 2（250 积分 ÷ 100） = 共 3 票。
       （仅读取积分，未扣减；按会员号强身份去重）
       共享榜：已匿名回流 GitHub ✅
    ```
  - 已投过（本机现在就是这个状态，可直接录）：
    ```
    该麦当劳会员已为《樱花麦旋风》投过票（每会员每单品仅一次），不能重复刷票。
    ```
- **口播**："这一步真的调了麦当劳 MCP 的 `query-my-account`：先确认会员身份，
  再按积分算票——积分只读取、不扣减。注意最后一行，共享榜同步成功与否是**单独说明**的。"

> 若没配置 `MCD_MCP_TOKEN`：这一段**不要伪造成功**。改拍"未配置时被明确拒绝"的画面，
> 口播改成"这就是它的限制：没有会员凭证就不投票，不降级、不匿名兜底"。
> 录制时加 `MCMUSEUM_SHARED_BOARD=0`，避免测试票写进正式共享榜。

  指顶部黄色「演示数据」横幅 + 榜单下方「⚠️ 演示数据 · 示例票数，非真实投票结果」。
- **口播**："左边是 GitHub 真实共享榜，每条票都是机器人匿名评论，只认机器人账号发的票。
  右边是演示模式的示例数据，**明确标注、且不提供投票入口**，所以演示票永远不会进正式榜。"
